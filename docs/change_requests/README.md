# Change requests

Se emerge una ragione tecnica seria per contestare una decisione consolidata, documentarla prima di proporne il cambiamento. Codex non modifica silenziosamente l'architettura; la decisione spetta alla supervisione. Nessuna CHANGE REQUEST è aperta in M0.

Una futura richiesta deve riportare:

- CHANGE REQUEST — titolo e riferimento alla baseline/ADR interessata.
- Problema scoperto.
- Evidenza, con test ID o riferimento verificabile.
- Impatto.
- Modifica proposta.
- Alternative.
- Rischio di non modificare.
- Test eventualmente necessari.

Registrare esito e decisione ricevuta; aggiornare STATE, aggiungere al LOG e aggiornare gli ADR solo in coerenza con l'esito autorizzato.
